not to change the project, submission, code repository or video after the
deadline and to leave them unchanged until the winner announcement. The public
rules list winners on or around October 14, 2026; this is not an automatic
unfreeze date. Confirm actual organizer instructions and announcement first.
The finalization notice is more explicit than the public rules page about edits;
this document records the notice rather than claiming the public rules contain
that exact wording.

## Team workflow

Before the deadline, record the final reviewed full commit SHA, deployment
version/URL, video URL and submitted artifacts in a submission snapshot. A tag
may aid traceability if created before the freeze, but is not itself permission
to keep editing the submitted repository. No final release is designated by this
document; development is still open before the deadline.

From the deadline, pause changes to the submitted repository (including other
branches, tags and releases), submission text/video and submitted app behavior.
Keep the judging demo accessible. Do not assume a separate branch or repository
is allowed for continued work: obtain organizer clarification about parallel
Wanted development before publishing it. Draft planning can remain local.
Ask the maintainer to resolve conflicting requests against the organizer notice.
Do not contact organizers automatically without the user's authorization.

Wanted's September 20 submission deadline does not override the earlier AWS
freeze. Do not change the shared demo or repository for Wanted during that freeze
without resolving the conflict with the organizers.

This is a documented team procedure, not an automated repository lock or a
scheduled task. The maintainer must perform the final snapshot and enforce the
freeze; no automation or branch protection is installed by these documents.
